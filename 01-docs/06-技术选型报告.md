# 06 · 技术选型报告

> 本章对后端、前端、数据库、PC 端、移动端、小程序、二维码、报表导出、部署九类技术分别给出 **2~4 个备选方案对比**（优缺点、成熟度、社区、信创适配度），并给出**选型结论与理由**，最后附**版本清单**。
> 选型结论与 [README](../README.md) 及 [07-软件架构设计](07-软件架构设计.md) 保持一致。

---

## 1. 后端框架选型

| 方案 | 优点 | 缺点 | 成熟度 | 社区 | 信创适配 |
|---|---|---|---|---|---|
| **Spring Boot 3.2（选定）** | 生态最全、MyBatis-Plus 无缝、JWT/POI/Hutool 齐全、Java 21 虚拟线程 | 启动内存较高 | 极高 | 极活跃 | 优（国产 JDK 兼容） |
| Quarkus | 启动快、内存小、GraalVM 原生 | 生态较新、既有组件少 | 中 | 活跃 | 一般 |
| Micronaut | 轻量、AOT | 国内资料少、招人难 | 中 | 一般 | 一般 |
| JFinal | 极简、上手快 | 生态小、企业级支撑弱 | 中 | 国内活跃 | 一般 |

**结论**：选 **Java 21 + Spring Boot 3.2**。理由：企业级进销存需要成熟的事务、安全、ORM 与报表生态；Java 21 虚拟线程提升高并发收银性能；国产 JDK（毕昇/龙井）对 Spring Boot 3 兼容性最佳，信创落地风险最低。

**持久层选型**：

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| **MyBatis-Plus（选定）** | 单表 CRUD 免写 SQL、分页/逻辑删除/乐观锁内置、易接多种数据库 | 复杂 SQL 仍需手写 | 选定：兼顾效率与可控 |
| JPA/Hibernate | 标准 ORM、跨库方言强 | 复杂统计 SQL 笨重、性能调优难 | 落选 |
| JdbcTemplate | 轻量可控 | 样板代码多 | 落选 |

## 2. 前端框架选型（B/S）

| 方案 | 优点 | 缺点 | 成熟度 | 社区 | 信创适配 |
|---|---|---|---|---|---|
| **Vue 3 + Element Plus（选定）** | 组合式 API、生态成熟、Element Plus 组件全、国产浏览器兼容好 | 需工程化配置 | 极高 | 极活跃 | 优（Chromium 内核兼容） |
| React + Ant Design | 生态大、社区广 | 学习曲线陡、模板多 | 极高 | 极活跃 | 优 |
| Angular | 企业级规范 | 重、上手慢 | 高 | 活跃 | 一般 |
| 低代码平台 | 开发快 | 定制受限、绑定厂商 | 中 | 一般 | 差 |

**配套**：`Vite`（构建）、`Pinia`（状态）、`Vue Router`（路由）、`Axios`（HTTP）、`ECharts`（图表）。

**结论**：选 **Vue3 + Vite + Element Plus + Pinia + ECharts**。理由：国内前端生态与人才储备最佳；Element Plus 覆盖表格/表单/树/上传等进销存高频组件；ECharts 满足 22 项统计与 15 张报表的可视化需求；对国产 Chromium 内核浏览器兼容良好。

## 3. 数据库选型

| 方案 | 优点 | 缺点 | 成熟度 | 社区 | 信创适配 |
|---|---|---|---|---|---|
| **MySQL 8（主，选定）** | 生态最广、性能好、成本低、开发调试方便 | 非国产 | 极高 | 极活跃 | 中（需国产替代） |
| **达梦 DM8（信创选定）** | 国产主流、Oracle 兼容度高、政务广泛使用 | 授权成本、生态较窄 | 高 | 国内活跃 | 优 |
| openGauss | 华为开源、性能强、社区活跃 | 运维要求较高 | 高 | 活跃 | 优 |
| Oracle | 功能强大 | 授权贵、非国产 | 极高 | 活跃 | 差（信创受限） |

**结论**：**MySQL 8 为主库**，**达梦 DM8 / openGauss 为信创兼容库**。理由：以 MySQL 开发调试效率最高；通过**通用 SQL 子集 + 适配层**（见 `02-database/dm/`）实现"一次开发、多库运行"；信创场景切换达梦/openGauss，满足国产化要求。

## 4. PC 端选型

| 方案 | 优点 | 缺点 | 成熟度 | 信创适配 |
|---|---|---|---|---|
| **Electron（选定）** | Web 技术栈复用、跨平台、可打国产 OS 包 | 体积较大、内存占用高 | 极高 | 良（麒麟/UOS 可打包） |
| Tauri | 体积小、Rust 内核 | 生态较新、Windows 外支持有限 | 中 | 一般 |
| Qt | 原生性能好、国产支持佳 | C++ 开发、与 Web 前端不共享 | 高 | 优 |
| 直接 B/S | 免安装 | 无本地能力（打印机/扫码枪） | — | — |

**结论**：选 **Electron**。理由：复用 Vue3 前端代码，降低维护成本；可访问本地设备（小票打印机、扫码枪）；能打包运行于麒麟/UOS/Windows，满足 PC 收银与门店客户端需求。

## 5. 移动端选型

| 方案 | 优点 | 缺点 | 成熟度 | 信创（鸿蒙）适配 |
|---|---|---|---|---|
| **uni-app（选定）** | 一套代码→Android/iOS/鸿蒙/小程序、生态成熟、Vue 语法 | 复杂原生能力受限 | 高 | 良（支持鸿蒙） |
| Flutter | 性能好、UI 一致 | Dart 语言、包体积大、鸿蒙生态待完善 | 高 | 中 |
| React Native | JS 生态、社区大 | 三端（含鸿蒙）支持弱 | 高 | 一般 |
| 各端原生 | 体验最佳 | 三端三套代码，成本高 | 极高 | 各端独立 |

**结论**：选 **uni-app**。理由：一套代码覆盖 **Android / iOS / 鸿蒙**，团队复用 Vue 技能；扫码、盘点等场景能力完备；对鸿蒙 Next 有官方支持路线，契合信创移动端要求。

## 6. 小程序选型

| 方案 | 优点 | 缺点 | 信创/生态 |
|---|---|---|---|
| **微信原生小程序（选定）** | 微信生态、体验好、扫码/支付能力强 | 仅微信端 | 微信生态 |
| uni-app 编译小程序 | 与 APP 共享代码 | 部分能力需适配 | 跨端 |
| Taro | 多端统一（React 语法） | 学习成本 | 跨端 |

**结论**：选 **微信原生小程序**（若需与 APP 最大复用可降级为 uni-app 编译小程序）。理由：书店私域主要沉淀在微信，原生能力（扫码、授权、订阅消息）最稳；作为轻量线上入口，与移动 APP 形成互补。

## 7. 二维码选型

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| **Hutool QrCode（选定）** | 纯 Java、零外部依赖、与后端同栈、集成简单 | 高级美化需扩展 | 选定：后端统一生成 |
| ZXing | 功能全、扫码/识别强 | API 较繁 | 备选（扫码识别可配合） |
| 前端 qrcode.js | 前端生成 | 无法统一落库 | 备选（纯展示场景） |

**结论**：后端用 **Hutool QrCode** 生成 PNG，内容规范（`SHG:BOOK:<isbn>` 等）统一由服务端落 `sys_qrcode`；扫码识别复用设备/小程序能力。

## 8. 报表导出选型

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| **Apache POI（选定）** | 功能全、支持 xlsx 样式/公式、与 Java 同栈 | 大文件内存占用高 | 选定：SXSSF 流式导出 |
| EasyExcel（阿里） | 内存友好、API 简洁 | 复杂样式受限 | 备选（简单报表） |
| iText/PDFBox | PDF 能力 | 非表格导出首选 | 备选（PDF 凭证） |

**结论**：选 **Apache POI（SXSSF 流式）** 导出 Excel，CSV 手写并加 UTF-8 BOM；兼顾复杂样式与大数据量内存控制。

## 9. 部署选型

| 方案 | 优点 | 缺点 | 信创适配 |
|---|---|---|---|
| **Nginx + JAR（选定）** | 简单、可控、静态资源与反向代理一体 | 手工运维 | 优（麒麟/UOS 均支持） |
| Docker Compose | 环境一致、易迁移 | 国产 OS 上 Docker 需适配 | 良 |
| K8s | 弹性、高可用 | 重、运维成本高 | 中 |
| 信创一体化平台 | 政企合规 | 绑定厂商 | 优 |

**结论**：中小书店以 **Nginx 反向代理 + Spring Boot JAR 裸机/容器部署**为主，数据库独立服务器；预留 Docker Compose 与 K8s 扩展能力。理由：部署简单、成本低、国产 OS 兼容好，符合书店行业 IT 现状。

## 选型总览结论

- **开发效率优先**：Java 生态（Spring Boot + MyBatis-Plus + POI + Hutool）与 Vue 生态（Vue3 + Element Plus + ECharts）为**行业最成熟组合**，人才与资料充足。
- **多端复用**：Electron（复用 Web）、uni-app（一套多端）显著降低多端成本。
- **信创可行**：数据库以「通用 SQL 子集 + 适配层」实现 **MySQL ↔ 达梦/openGauss** 兼容；JDK/OS/CPU 均有国产替代路径（详见 [10-信创适配方案](10-信创适配方案.md)）。
- **成本可控**：主库 MySQL 开源零成本，报表/二维码组件均开源，符合中小书店预算。
